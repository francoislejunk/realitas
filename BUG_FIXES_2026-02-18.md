## Summary
Fixed three critical bugs affecting obstacle movement, NPC name persistence, and background action processing.

## Bug #1: Obstacles Moving Inappropriately ✅ FIXED

### Issue
Obstacles and INUAs were being repositioned every time the map synced, even when no action was taken on them. This caused furniture and objects to "drift" or change positions between turns.

### Root Cause
**File:** `pygame_spatial_map.py:3137-3139`

The `sync_from_spatial_context()` function was re-syncing obstacles from cached layouts even when staying in the same location. This line:
```python
if not dims.obstacles:
    _sync_llm_obstacles_to_spatial_context(cached_layout, dims, scale_x, scale_y, session_id)
```

Was being called every sync, causing obstacles to be repositioned based on LLM-generated positions rather than their actual simulation state.

### Fix Applied
**File:** `pygame_spatial_map.py:3133-3142`

Changed obstacle sync logic to ONLY sync on first load of a new location:
```python
elif use_cached_layout:
    # Same location - just update actors, DON'T regenerate layout or move obstacles
    print(f"[PMAP] ✓ Same location '{location_name}', updating actors only (obstacles remain stationary)")
    # Never re-sync obstacles when using cached layout for same location
    # This ensures obstacles only move when explicitly acted upon by player/NPC
    # Only sync obstacles if spatial context is completely empty (first load only)
    if not dims.obstacles and location_name != current_location:
        print(f"[PMAP] First load: Syncing obstacles from cached layout to spatial context")
        _sync_llm_obstacles_to_spatial_context(cached_layout, dims, scale_x, scale_y, session_id)
```

### Result
- Obstacles now remain stationary unless explicitly moved by player/NPC actions
- Map layout persists correctly across turns
- Proper spatial persistence maintained

## Bug #2: NPC Names Changing During Location Session ✅ FIXED

### Issue
NPC names would change after taking turns, causing name-based lookups to fail in encounter processing. This resulted in NPCs "disappearing" from encounters or being unable to complete their turns.

### Root Cause
**Files:**
- `MAIN/redesigned_main.py:2706-2707` (mention restoration)
- `MAIN/redesigned_main.py:9152` (spatial restoration)

During NPC restoration from mentions or spatial context, names were being unconditionally reassigned:
```python
actor_obj.sheet.name = name  # Always overwrites, even for existing actors
actor_obj.name = name
```

This created a race condition where:
1. NPC enters turn queue with name "Marcus Stone"
2. Mid-turn, mention system restores "Marcus" and overwrites name
3. Turn lookup for "Marcus Stone" fails → encounter breaks

### Fix Applied
**File:** `MAIN/redesigned_main.py:2706-2710, 2724-2727`

Added conditional name assignment to prevent overwriting existing names:
```python
# ONLY set name if we're creating a brand new actor
# Don't overwrite names of existing actors in registry
if actor_obj.sheet.name != name:
    actor_obj.sheet.name = name
    actor_obj.name = name

# Register with canonical name - prevents duplicate registrations
if name not in actor_registry:
    actor_registry[name] = actor_obj
```

**File:** `MAIN/redesigned_main.py:9154-9159`

Same fix for spatial restoration:
```python
# ONLY set name during initial creation, not during restoration
# This prevents name changes mid-session
if nua.sheet.name != nm:
    nua.sheet.name = nm
```

### Result
- NPC names persist from initial spawn throughout entire location session
- Name-based lookups work correctly in turn processing
- Encounter mode properly matches actors across turns
- Actor registry prevents duplicate spawns

## Bug #3: Background Actions Not Processing Through Goal/Task System ✅ FIXED

### Issue
NPC background actions (roaming, watching encounters, etc.) were generated but never updated their goal/task managers. This meant NPCs' personal goals never progressed from background activities, breaking character consistency.

### Root Cause
**File:** `agents/background_simulation_system.py:1091-1108`

The `_execute_nua_turn()` function generated narratives, updated positions, and recorded to tracker, but never called goal/task system updates. Compare with UA actions which call `conductor.interpreter.update_actor_tasks()` at lines 14201, 16336, 19281 in main loop.

Similarly, `simulate_excluded_actors_during_encounter()` (lines 281-333) generated background actions but never processed them through task systems.

### Fix Applied
**File:** `agents/background_simulation_system.py:1109-1133`

Added goal/task system integration to NPC roam actions:
```python
# CRITICAL: Update NPC goal/task system (mirror UA action processing)
# This ensures NPC background actions properly update their goals and tasks
try:
    if hasattr(actor, 'goal_task_manager') and actor.goal_task_manager:
        # Update tasks based on the action performed
        actor.goal_task_manager.update_goal(
            action_taken=narrative,
            outcome="success",  # Background actions are assumed successful
            context=f"Roam action: {action_type}"
        )
        print(f"{Color.CYAN}[GOAL/TASK] Updated {actor.sheet.name}'s goals/tasks from roam action{Color.RESET}")
    elif hasattr(self, 'interpreter') and self.interpreter and hasattr(self.interpreter, 'update_actor_tasks'):
        # Fallback: use interpreter's task update system if available
        self.interpreter.update_actor_tasks(
            user_action=narrative,
            actor=actor,
            action_interpretation=action_data
        )
        print(f"{Color.CYAN}[GOAL/TASK] Updated {actor.sheet.name}'s tasks via interpreter{Color.RESET}")
except Exception as goal_e:
    # Non-critical: goal/task updates are enhancement, don't break simulation
    pass
```

**File:** `agents/background_simulation_system.py:333-346`

Added goal/task updates for encounter background actions:
```python
# Update NPC goal/task system for background actions during encounters
try:
    if hasattr(actor, 'goal_task_manager') and actor.goal_task_manager:
        action_description = narratives.get(action_type, f"{actor_name} remains in the area.")
        actor.goal_task_manager.update_goal(
            action_taken=action_description,
            outcome="success",
            context=f"Background action during encounter: {action_type}"
        )
        print(f"{Color.CYAN}[GOAL/TASK] Updated {actor_name}'s goals/tasks from encounter background action{Color.RESET}")
except Exception:
    pass  # Non-critical
```

### Result
- NPC background actions now properly update goals/tasks
- Character consistency maintained across roaming and encounter modes
- NPCs' personal objectives progress naturally
- Mirrors UA action processing pattern for consistency
