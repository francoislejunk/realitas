# Memory Intents Always Return EXIST - Fixed Intent Availability

## The Problem

Memory recall intents were being classified as `EXIST_NOT_HERE`:

```
User: "I try and remember my bestfriend"
↓
Intent Availability: exist_not_here
Reason: "We're not at a place where we can remember..."
↓
❌ No memory created
❌ No internal voice
❌ Generic diegetic message
```

This is wrong because:
- **Memories are mental** - not location-dependent
- **Always accessible** - can recall anywhere
- **Should return EXIST** - trigger memory creation

## The Root Cause

Intent availability system treated memories like physical objects:

```python
# System checked:
"Best friend" → Is it physically here? → NO → EXIST_NOT_HERE

# Should have been:
"Best friend" → Is this a memory? → YES → EXIST
```

## The Solution

Added special case detection for memory recall intents:

```python
# Special case: Memory recall and mental intents are always EXIST
memory_patterns = [
    'try to remember', 'try to recall', 'trying to remember', 
    'trying to recall', 'i remember', 'i recall', 
    'think about', 'think back', 'reminisce'
]

if any(pattern in user_intent_lower for pattern in memory_patterns):
    return {
        "availability": IntentAvailability.EXIST,
        "internal_voice": None,  # Generated by memory system
        "reasoning": "Memory recall is a mental action and always available"
    }
```

All return `EXIST` immediately without checking location.

## Location Independence

**Mental actions don't depend on location:**

```
At home: "I try to remember my best friend" → EXIST
At work: "I try to remember my best friend" → EXIST
In a car: "I try to remember my best friend" → EXIST
Anywhere: "I try to remember my best friend" → EXIST
```

**Physical actions DO depend on location:**

```
At home: "I use my laptop" → EXIST (laptop is here)
At work: "I use my laptop" → EXIST_NOT_HERE (laptop at home)
In a car: "I use my laptop" → EXIST_NOT_HERE (laptop elsewhere)
```
